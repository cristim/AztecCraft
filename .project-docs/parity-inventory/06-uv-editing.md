# UV editing

Status: expanded for the UV menu. ID prefix `UVE`. The UV Editor menu bar, its
toolbar and marking menus, and the UV-set/UDIM workflows they carry (Unfold,
Relax, pinning, layout and packing, texel density) are a follow-up audit of the
[UV Editor menu bar](https://help.autodesk.com/cloudhelp/2027/ENU/Maya-Modeling/files/GUID-56EDB7E4-8B29-4705-BF4D-2D860F08BBB4.htm)
page and are not yet inventoried here. Framework and rules: [README.md](README.md).

Owner issues (open feature, epic or verification issues): #53, #360

- Native check on 2026-10-31: a debug `mcp` build on Linux in a private `kwin_wayland --virtual` session with fake pointer input, at 1600 by 1000. Real clicks opened the UV menu, the Planar option box and the UV Editor, and Apply on a sphere gave 400 faces and undo label `Planar Mapping`. The layout was looked at: a Y projection of the sphere draws the expected radial pattern, and a Y projection of a cube draws on the square's border only, which is correct. With nothing selected, Apply is disabled and the editor says why. Keyboard use, other window sizes and other platforms were not driven natively. No Maya comparison. Screenshots are not distributed.

## Evidence record

- Documentation: Maya 2027.2 help. The [UV menu](https://help.autodesk.com/cloudhelp/2027/ENU/Maya-Modeling/files/GUID-3100AC8D-C82C-4F17-A556-39760FEE91AC.htm) page was fetched as full text and read on 2026-11-20 (a 2026-11-14 read is superseded). The options pages cited per row are the URLs linked from that menu page (resolved 2026-11-20); they were not read, so every option default remains PROVISIONAL and the Doc cells cite them as destinations, not as audited text. Component: Maya core (no plug-in).
- Repository SHA at which Evidence was checked: origin/main 01147409.
- Test platforms: per-test table under "Test platforms" at the end of this file (audited at origin/main 01147409).
- Fixtures: synthetic in-test scenes (`src/native_scene/session_uv/tests.rs`, `src/mcp_tests/official_client/uv.rs`); none is hashed.
- Scope: the documented behaviour of the cited pages only. Maya's projection and seam algorithms are not compared (no Maya run, #5). Statuses describe documentation conformance, not Maya parity.
- Dimensions: interaction, semantic output, persistence, undo, invalid input, interop.
- Menu state on main: the UV menu is drawn with its documented 2027 labels in page order (`src/app/features/uv.rs`); UV Editor, Planar and Delete UVs are enabled (UVE-001 to UVE-003), every other row is disabled with a reason (`src/app/features/uv.rs "disabled_rows"`), with no invented items; the UI side is the [UI inventory](../ui-parity-inventory.md) "Per-set menu lists" row, not copied here.
- The Maya command names behind the audited items (`polyCylProj`, `polySphProj`, `polyAutoProj`, `polyMapCut`, `polyMapSew`, `polyMergeUV`, `polySplitUV`, `polyForceUV`) appear nowhere in `src` or `tests` except inside the binary fixture `tests/fixtures/gt-tools/dummy_mesh.mb`; greps were run at the SHA above.
